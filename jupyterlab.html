JupyterLab Setup

JupyterLab runs on Spark itself, but you view and use it through a regular web browser on your own machine (or inside the VDI virtual desktop). It gives you a file browser, a code/text editor, notebooks, and a terminal — useful especially if you're on the VDI, which doesn't have VS Code.

01 Install JupyterLab

One-time setup, inside your own conda environment.

Assumes you've already set up your own Miniconda and created an environment. Activate it, then install JupyterLab into it:

conda activate myenv
pip install jupyterlab

02 Launch JupyterLab

Bind it to localhost only, and let it pick its own port.

jupyter lab --no-browser --ip=127.0.0.1 --port=0
Why these flags: --ip=127.0.0.1 keeps the server reachable only from Spark itself, not the open network — you'll reach it securely through the SSH tunnel below instead. --port=0 lets Jupyter pick a free port automatically, so you don't collide with another student who happens to also be running JupyterLab right now (the default port, 8888, is first-come first-served and this box has multiple students on it).

When it starts, it prints something like this — copy the full URL, you'll need the port number and token:

Jupyter Server 2.21.1 is running at:
http://127.0.0.1:8899/lab?token=483b8f0c565ee4db71bdbec072d8662dc4dc0da601483f42

Leave this terminal window open for as long as you want to use JupyterLab — closing it (or disconnecting) stops the server. If that happens, just run the command again to start a new one.

03 Connect From Your Browser

Open a second terminal and forward the port over SSH, then open the URL in a browser.

The JupyterLab server only listens on Spark's own localhost, so you need an SSH tunnel to reach it. Open a second terminal window (in the VDI virtual desktop, or on your own machine if you're on campus network) and run:

ssh -L 8899:localhost:8899 your-username@spark.cs.montclair.edu

Replace 8899 with whatever port your jupyter lab command actually printed (from step 2) — both numbers in the command need to match that port. Keep this second terminal open; it's just holding the tunnel, you don't need to do anything else in it.

Now open a browser inside the same VDI desktop (or on your own machine, if you SSH'd directly) and paste in the full URL Jupyter printed in step 2, for example:

http://127.0.0.1:8899/lab?token=483b8f0c565ee4db71bdbec072d8662dc4dc0da601483f42

JupyterLab should load. The token in the URL is your authentication — don't share it with anyone else, it's equivalent to a password for whatever's running under your account.

04 Using JupyterLab

The file browser on the left is your home directory on Spark.

  • Upload a file: click the upload icon (↑) at the top of the file browser panel, or just drag a file from your computer into the browser window.
  • Download a file: right-click it in the file browser → Download.
  • Edit code/text: double-click any file to open it in an editor tab.
  • Run a notebook: File → New → Notebook, pick the kernel matching your conda environment.
  • Open a terminal: File → New → Terminal — this is a real shell on Spark, same as SSH.

05 Reconnecting Later

If the terminal running JupyterLab is still open and you just lost the browser tab or forgot the URL, you don't need to launch it again.

jupyter lab list

Run this from a new terminal window (a fresh SSH connection is fine). It prints the URL (with port and token) of any JupyterLab server still running under your account. Re-open the SSH tunnel from step 3 using that port, then open that URL in your browser.

06 Troubleshooting

ProblemTry this first
Browser can't reach the localhost URL Check the SSH tunnel terminal is still open and didn't error out. Confirm the port number in the tunnel command matches the port in the URL exactly.
"Address already in use" when launching Use --port=0 as shown above instead of a fixed port — it picks a free one for you.
Lost the token/URL Run jupyter lab list if it's still running, or restart it and copy the new URL.
JupyterLab stopped when I closed my terminal That's expected — the terminal running jupyter lab needs to stay open the whole time. Just run the command again to start a new one.
